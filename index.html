Chapter 01–02

Luồng Khởi Động (Backend + Frontend)

Backend Startup Sequence

Tầng 1 — Security + Bootstrap Guard

Kiểm tra JWT_SECRET, REFRESH_TOKEN_SECRET, SECRET_KEY ở non-dev và validate SUPERADMIN_BOOTSTRAP_MODE. Sai mode hoặc thiếu secret là fail-fast ngay.

Tầng 2 — Database / Cache / Media Readiness

connect_db() → assert_transaction_capability() → optional media_storage.check_backend_health() khi media đi qua S3-compatible backend.

Tầng 3 — Seeding + Runtime Prep

admin_service.ensure_roles() và ensure_super_admin(), sau đó verify_runtime_storage() hoặc ensure_runtime_storage() tùy môi trường.

Tầng 4 — Recovery + Background Workers

Refresh transaction readiness, start readiness loop, recover audio task sau restart, load recent tasks, start maintenance loop, ensure runtime observability indexes rồi bật analytics worker và media cleanup worker.

Gắn 10 Routers + /static + readiness

content, audio, admin, owner, ai_advisor, analytics, localization, maps, runtime_observability, ui_i18n — kèm /static, /health, /health/ready.

Frontend Startup Flow

SW Register → React Router (catch-all) → Splash Screen → Chọn ngôn ngữ → Parallel Load

🧭 Best-Effort Locate

requestBestEffortPosition() ưu tiên cached result nếu còn tốt; budget mặc định 15s, cache age 30s, accuracy chấp nhận tới 100m.

💾 Offline Snapshot

getOfflinePOIs(lang) và cached UI bundles từ IndexedDB giúp app render ngay cả khi backend chưa phản hồi.

🌐 Delta Sync Content

loadAllPOIs(lang) dùng ETag, dataset_version và updated_after để full sync hoặc delta sync rồi cập nhật IDB.

🔥 Hotset Readiness

prepare-hotset lấy tối đa 10 POI gần nhất trong 1.5km; thực tế switch chỉ coi là sẵn sàng khi 3 POI bắt buộc đã được cache.

🧩 UI Bundle + Warmup

Startup coordinator tách readiness giữa content locale và UI bundle. App có thể quick-start bằng English trong khi /warmup và /ui-bundles tiếp tục hoàn tất dưới nền.

Startup probe: trước khi kết luận backend đang lỗi mạng, frontend thử chuỗi /api/v1/audio/languages và /api/v1/maps/offline-options với timeout 2.5 giây, tối đa 2 lần trong cửa sổ 8 giây.

Chapter 04

GPS + Geofence + Audio Narration

Luồng geofence hiện xử lý đồng thời nhiễu GPS, tiết kiệm pin, chuyển ngôn ngữ giữa chừng và fallback audio nhiều tầng. Ba hằng số dễ nhớ nhất là debounce 3 giây, GPS throttle 5 giây và cooldown 5 phút.

4 Giai Đoạn Xử Lý

Giai đoạn 1 — GPS Collection (LocationService)

watchPosition() liên tục → throttle 5s để tránh render/sort liên tục. Khi user bấm locate, app dùng thêm requestBestEffortPosition() để tận dụng cached fix nếu đủ tốt.

Giai đoạn 2 — Zone Detection (GeofenceEngine)

checkGeofences(pos): turf.distance() tính khoảng cách. ≤ radius (default 30m) → pendingEntries. Ra ngoài zone đã trigger → cooldown 5 phút.

Giai đoạn 3 — Audio Decision (Safety Reconcile 5s)

_reconcileLoop() được gọi khi có position update và còn có safety reconcile 5s: confirm ENTER sau 3s debounce → chọn POI theo audio_priority rồi đến khoảng cách → đẩy NarrationEngine.

Giai đoạn 4 — Audio Playback (4-Tier Hybrid)

NarrationEngine → AudioQueueManager (single-slot priority queue) → playWithFallback(). Kết quả on-demand cũ sẽ bị bỏ nếu user đã đổi ngôn ngữ trong lúc chờ.

4-Tier Hybrid Audio

Tier 1
Pre-generated Audio (0ms) playAudioUrl(poi.audio_url) → SW CacheFirst → phát từ cache. Điều kiện: có audio_url, không phải is_fallback.
Tier 1.5
On-demand Translate + TTS (2-5s) POST /localizations/on-demand → Backend dịch + Edge-TTS → lưu → trả audio_url mới. Khi POI có is_fallback=true.
Tier 2
Cloud TTS Stream (3-8s) POST /audio/tts → Edge-TTS synthesis → stream MP3 trực tiếp. Disk cache cho lần sau.
Tier 3
Local Speech Synthesis (0ms) window.speechSynthesis — offline fallback cuối cùng. Chất lượng thấp hơn nhưng luôn khả dụng.
Background Prefetch: Song song, _prefetchNearbyLocalizations(pos) quét dataset POI đang có trong store, lọc POI is_fallback=true trong 500m, enqueue tối đa 3 POI mỗi đợt rồi drain tuần tự. Đợt mới chỉ mở sau tối thiểu 30 giây; nếu gặp 429 thì backoff 30s → 60s → 120s ... tối đa 10 phút.

Chapter 05

Module Content — POI Lifecycle

GET /poi/load-all

API nặng nhất. Hỗ trợ full sync hoặc delta sync bằng If-None-Match + updated_after; trả thêm dataset_version, sync_mode, removed_poi_ids, sync_cursor. Active public lane chỉ trả POI đã sẵn sàng tiếng Anh.

GET /poi/nearby

Ưu tiên $geoNear trên index không gian để lấy POI trong bán kính; nếu geo query lỗi thì fallback sang Haversine sort in-memory. Dùng cho hotset và nearby discovery.

Create / Update POI

Lưu text trước, sau đó queue audio cho 5 ngôn ngữ ưu tiên. Khi mô tả đổi, hệ thống xóa audio_url cũ, set audio_status="processing", tạm giữ is_active=false và nhớ activation_requested.

Delete / Activation Gate

Xóa POI theo transaction khi có thể, cascade sang poi_localizations, enqueue media cleanup và touch dataset version. Bật public mà chưa ready English/audio thì vẫn phải regenerate trước.

Runtime audio decoration: trước khi trả frontend, backend gắn ?v={updated_at}&l={lang} vào audio_url để vừa cache-bust khi file đổi, vừa giúp Service Worker shard cache theo ngôn ngữ.

3-Tier Content Fallback

Tier 1
Ngôn ngữ yêu cầu Trả đúng ngôn ngữ user chọn nếu trong poi_localizations đã có bản dịch và audio.
Tier 2
English Fallback Fallback chung cho khách quốc tế. Nếu rơi xuống tầng này thì frontend biết đây là nội dung thay thế.
Tier 3
Nguyên bản tiếng Việt Lớp phòng thủ cuối. audio_url = null để frontend chuyển sang on-demand hoặc tier audio khác.

Chapter 06

Module Audio / TTS

TTSService — Nhà Máy Audio

  • translate_text(): deep-translator (GoogleTranslator) — miễn phí
  • generate_audio(): dịch → Edge-TTS synthesis → lưu MP3
  • Cache key: MD5(f"{text}:{lang}") → file tồn tại = Cache HIT, zero cost
  • 5 preferred voices: vi (HoaiMyNeural), en (JennyNeural), zh (XiaoxiaoNeural), ja (NanamiNeural), ko (SunHiNeural)

AudioTaskManager — Background Engine

  • Parallel generate với Semaphore max=3
  • SSE real-time: GET /admin/audio-tasks/stream
  • Frontend: progress bar + Pause/Resume/Cancel
  • Status: queued → running → paused → completed/failed/cancelled

POST /audio/tts (Tier 2 API)

  • Text → Edge-TTS → stream MP3 trực tiếp
  • Disk cache: X-Cache: HIT/MISS
  • X-Static-Url: versioned URL cho SW cache

GET /audio/pack-manifest

  • Quét tất cả MP3 cho 1 lang
  • Tính SHA-256 hash per file
  • Return: {lang, pack_version, total_files, total_bytes, files[]}

Audio Generation Pipeline

Source Text (VN) → deep-translator → Translated Text → MD5 Hash Check → Edge-TTS → MP3 File → Upsert Localization

Chapter 07

Authentication & RBAC

🔐 httpOnly Cookie Auth

  • access_token: JWT, 30 phút, httpOnly, SameSite=Lax, Secure
  • refresh_token: JWT, 7 ngày, httpOnly
  • JS không đọc được (chống XSS), SameSite chống CSRF
  • Dual-mode: Cookie (browser) + Bearer header (API/mobile fallback)

🔑 Dynamic RBAC

  • Static: 32 permissions / 9 domains (code)
  • Dynamic: Roles in MongoDB (DB)
  • Route Guards: require_permission("poi:delete")
  • JWT payload chứa permissions → không cần query DB cho hầu hết request

Chapter 08

Localization + UI Bundles — Đa Ngôn Ngữ 2 Làn

Làn 1 — Content Locale

GET /poi/load-all?lang=ja hydrate poi_localizations theo target → English → Vietnamese. Đây là lane nội dung POI, độc lập với UI text.

Làn 1.1 — Hotset

prepare-hotset làm nóng tối đa 10 POI gần nhất trong 1.5km. Frontend chỉ coi switch là ready khi 3 POI bắt buộc đã có đủ content/audio trong cache.

Làn 1.2 — On-demand + Warmup

POST /localizations/on-demand xử lý reactive theo POI; POST /warmup chạy full-corpus dưới nền. Khi bị limiter chặn, backend trả Retry-After để frontend backoff đúng nhịp.

Làn 2 — UI Bundles

GET /api/v1/ui-bundles/{locale} phục vụ namespace public-ui. 5 ngôn ngữ top-level (en, vi, zh, ja, ko) có bundle tĩnh; long-tail locale trả English fallback với status: pending và source_hash trong lúc server dịch nền.

Điểm mấu chốt: đổi ngôn ngữ bây giờ không chỉ là chờ bản dịch POI. Frontend chỉ coi một language switch là hoàn tất khi cả content hotset lẫn UI bundle đều ready. Vì vậy app có thể quick-start bằng English, sau đó chuyển hẳn sang ngôn ngữ đích khi cả hai làn đã đủ dữ liệu.

Chapter 09

Offline / PWA — 4 Lớp Phòng Ngự

Lớp 1 — Service Worker Strategies

sw.js dùng injectManifest + Workbox. Chiến lược chính:

  • POI data: NetworkFirst 8s, cache poi-load-all-cache, 15min TTL
  • Audio: CacheFirst per-lang, cache audio-cache-lang-{lang}
  • Images + optional runtime chunks: CacheFirst, quota-aware purge
  • Map pack: custom immutable cache + activate/deactivate message lane

Lớp 2 — Language Sharding + Build Sync

Mỗi ngôn ngữ là một shard cache riêng; đồng thời runtime chunk cache riêng giúp public app không bị kẹt asset cũ sau deploy.

  • Max 300 files / ngôn ngữ
  • Max 3 ngôn ngữ đồng thời
  • LRU eviction: xóa lang ít dùng nhất
  • APP_BUILD_SYNC dọn public-optional-chunk-cache khi build đổi

Lớp 3 — IndexedDB (Quan4DB v2)

Lưu pois_by_lang và cached UI bundles để app còn dữ liệu ngay cả khi SW/network miss.

  • Offline Fallback: target → en → vi
  • Bỏ qua is_fallback=true trong target lane
  • User không bao giờ thấy màn hình trống

Lớp 4 — Offline Packs

Bundle explicit theo ngôn ngữ đang chọn gồm 4 phần: map + POI + images + audio.

  • Install tuần tự: map → POI → images → audio
  • SHA-256 verify cho từng asset trước khi activate
  • Pack cache tách biệt khỏi runtime cache
  • Action summary: updateAvailable, repairRequired, poiMissing
  • purgeOnQuotaError: true → hy sinh runtime khi disk đầy

SW Message Protocol

Message Từ Mục đích
SET_ACTIVE_LANGUAGE Frontend Ghim shard ngôn ngữ đang dùng để eviction ưu tiên giữ đúng audio cache hiện hành
APP_BUILD_SYNC Runtime build sync Dọn optional chunk cache cũ sau deploy để public shell không bị mix asset giữa hai build
AUDIO_PACK_ACTIVATE AudioPackService Audio pack tải xong → set active cache để SW ưu tiên pack thay cho runtime MP3 lẻ
AUDIO_PACK_REMOVE_LANG AudioPackService Xóa audio pack → cleanup toàn bộ cache audio của ngôn ngữ đó
MAP_PACK_ACTIVATE MapPackService Map pack install → activate cache mới để map runtime đọc pack vừa verify xong
MAP_PACK_DEACTIVATE MapPackService Xóa map pack → cleanup PMTiles/style/font cache và trả app về lane cloud thuần
Edge Case — Disk Full: Khi tải Pack mà hết dung lượng → QuotaExceededError → Workbox tự xóa runtime cache (audio-cache-lang-*) + image cache (có purgeOnQuotaError: true) để nhường chỗ cho Pack. "Hy sinh cái nhỏ, giữ cái lớn."
Remote update checks: nếu remote manifest lỗi liên tiếp, lane kiểm tra update sẽ tự vào cooldown thay vì spam network. Điều này áp dụng cho cả Map Pack và Offline Bundle status.

Chapter 10

Map Pack — PMTiles Offline

Map pack hiện đi theo mô hình static-first: manifest và asset chính đi qua /static/maps/*, còn /api/v1/maps/* giữ vai trò compatibility layer. Frontend có thể giữ nhiều pack theo scope (ví dụ Quận 4 / TP.HCM), phát hiện update bằng cả version lẫn manifest fingerprint rồi mới activate qua pmtiles://.

Chuỗi Liên Kết 4 Tầng (End-to-End)

Tầng Thành phần chính Vai trò
1. Mode Selection mapConfig.js (Cloud / Offline / Hybrid) Chọn chiến lược render theo trạng thái mạng và pack đã kích hoạt.
2. Pack Publication Static tree /static/maps/* + compatibility /api/v1/maps/* Manifest công bố version, checksum, scope, source_date, bbox và absolute asset URLs.
3. Pack Activation Frontend downloader + SHA-256 verify + safe/replace update Tải tài nguyên, xác thực toàn vẹn rồi mới activate; nếu pack khác scope đang chiếm chỗ thì có thể yêu cầu replace_update.
4. Runtime Rendering MapLibre + pmtiles:// Render từ local cache; hybrid vẫn giữ cloud fallback và probe dựa trên active cloud style thật.

3 Chế Độ Bản Đồ

☁️ Cloud (Default)

Project-owned cloud style template, glyphs tự host và vẫn cần VITE_MAPTILER_KEY cho dữ liệu cloud.

📦 Offline Pack

PMTiles + local style/glyphs tự host. Có thể active pack theo scope như Quận 4 hoặc TP.HCM, đọc từ Cache API sau khi verify và activate.

🔄 Hybrid Q4

Cloud-first, tự fallback sang pack local khi probe cloud fail hoặc thiết bị offline; recovery về cloud có độ trễ để tránh flip-flop.

Chapter 11

Admin Dashboard + Owner Portal + AI Advisor

Platform 3 cổng: Owner (B2B), Admin (vận hành), AI Advisor (nâng cấp nội dung).

🏪 Owner Portal

  • Đăng ký public: POST /admin/auth/register-owner
  • Admin duyệt → is_verified=true + is_poi_owner_verified=true
  • Quản lý POI: PUT /owner/pois/{id} (chỉ quán mình)
  • Submissions → Admin phê duyệt mới lên app; review note dùng field chuẩn admin_note
  • Notification bell + detail page lấy từ /owner/notifications*
  • PII Encryption: CCCD mã hóa Fernet

🎛️ Admin Dashboard (40 admin routes; +12 owner routes = 52 total)

  • CRUD: POIs, Users, Roles, Menus
  • Kiểm duyệt: Registrations, Submissions
  • Auth: /admin/auth/me, POST /admin/auth/change-password
  • Giám sát: Analytics read models, Audit Logs, runtime observability window
  • SSE: Audio Tasks progress real-time

🤖 AI Advisor (Gemini 2.5 Flash / ProxyPal)

  • GET /ai/usage + POST /ai/enhance-description
  • Prompt: KHÔNG bịa, CÓ THỂ thêm tính từ tích cực, 200-300 từ
  • Rate limit: Owner = 10/ngày (OWNER_DAILY_LIMIT, collection ai_usage_limits)
  • Admin = unlimited
  • Timeout: 30s, fallback provider rõ ràng cho UI

Owner Registration Flow

Chủ quán đăng ký → Tạo user (poi_owner, unverified) → Tạo poi_owner_registrations (pending) → Admin duyệt → user verified + owner verified → Owner login → /owner
Owner UX mới: sau review, owner nhận notification trong app; trang dashboard, submissions, notifications và POI pages đều chỉ fetch khi tài khoản đã qua gate is_poi_owner_verified.
Analytics semantics: public analytics chỉ bắt đầu sau khi user grant consent. tracked_online_users là số anonymous device đã consent còn trong sliding window hiện tại, không phải tổng traffic hay số tab đang mở.
